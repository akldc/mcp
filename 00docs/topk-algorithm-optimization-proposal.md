# RAG 工具检索 Top-K 算法优化建议

## 1. 目标

当前 `VectorIndex::search()` 对全部工具计算余弦相似度，再对全部结果执行 `std::sort`，最后截取前 K 项。

设工具数量为 `N`、向量维度为 `D`：

- 相似度计算：`O(ND)`
- 全量排序：`O(N log N)`
- 结果数组：当前会复制完整 `IndexedTool`，额外空间接近 `O(ND)`

优化目标是在保持精确召回、结果可解释和实现难度适中的前提下，将排序阶段降低为与 K 相关的复杂度，并减少 embedding 的无效复制。

## 2. 推荐方案：固定容量最小堆

遍历索引时维护一个最多包含 K 个候选的最小堆。堆顶始终是当前 Top-K 中最差的候选：

1. 计算一个工具与查询的相似度。
2. 低于 threshold 时立即跳过。
3. 堆未满时直接插入。
4. 堆已满且新候选优于堆顶时，弹出堆顶并插入新候选。
5. 遍历结束后，只对堆内最多 K 个候选执行降序排序。

复杂度：

- 相似度计算：`O(ND)`
- 堆维护：`O(N log K)`
- 最终排序：`O(K log K)`
- 候选空间：`O(K)`

当 `K << N` 时，相比全量排序的 `O(N log N)` 更合适，也很适合作为面试项目中的算法优化点。

建议堆节点只保存：

```cpp
struct Candidate {
    const IndexedTool* tool;
    float similarity;
};
```

不要在遍历阶段复制 `IndexedTool` 和 embedding。确定最终 K 个工具后，再构造对外的 `SearchResult`。

## 3. 稳定排序规则

当前索引使用 `unordered_map`，相同相似度的候选顺序不稳定。建议统一定义：

1. 相似度高的排前面。
2. 相似度相同时，工具名称字典序小的排前面。

最小堆的“最差候选”则是：相似度更低；相似度相同时，名称字典序更大。

这样可以保证同一数据集和查询得到稳定结果，也方便写确定性的单元测试。

## 4. 输入与数值边界

实现新算法时应同时保留或增加以下检查：

- `top_k <= 0`：直接返回空结果。
- `top_k > N`：最多返回有效候选数量。
- 查询向量为空：返回空结果。
- 查询向量和工具向量维度不一致：跳过该工具并记录索引异常指标。
- 零向量：跳过，避免把无效相似度当作正常候选。
- similarity 为 `NaN` 或 `Inf`：跳过。
- threshold 应在配置加载阶段校验；余弦相似度理论范围是 `[-1, 1]`。

是否在“没有候选达到 threshold”时返回最佳项属于产品策略，不应隐藏在 Top-K 算法内部。建议由上层显式选择严格阈值、最佳努力或全量回退。

## 5. 可选方案：`std::nth_element`

另一种实现是：

1. 计算全部轻量候选并预先过滤 threshold。
2. 使用 `std::nth_element` 将前 K 名移动到数组前部。
3. 只对前 K 名执行 `std::sort`。

平均复杂度为：

- 候选选择：`O(N)`
- 前 K 排序：`O(K log K)`
- 额外候选空间：`O(N)`

它的代码通常比优先队列更直接，在 `K` 较大时也可能更快；缺点是仍需保存所有候选。建议把它作为基准对照方案，而不是同时保留两套生产实现。

## 6. 向量计算的后续优化

Top-K 选择只优化排序部分，`O(ND)` 的向量计算通常仍是主成本。后续可做：

### 6.1 预归一化工具向量

工具入库时完成 L2 归一化，查询时只归一化一次。搜索阶段的余弦相似度就可简化为点积：

```text
cosine(q, x) = normalized(q) dot normalized(x)
```

这样避免为每个工具重复计算工具向量范数和平方根。

### 6.2 连续内存布局

`unordered_map<string, IndexedTool>` 适合按名称更新，不适合高吞吐向量扫描。可以同时维护：

- 名称到工具位置的哈希索引；
- 连续存储的归一化向量矩阵；
- 与矩阵行一一对应的工具元数据。

连续内存更利于 CPU cache 和后续 SIMD 优化。

### 6.3 ANN 的采用边界

当前场景优先保留精确搜索。只有满足以下条件时再考虑 HNSW、FAISS 等近似索引：

- 工具数量达到数万级；
- 精确扫描无法满足 P95 延迟目标；
- 可以接受近似召回；
- 有离线数据衡量 Recall@K 的损失。

对于常见的几十到几千个 MCP 工具，最小堆加预归一化通常已经足够。

## 7. 建议实现步骤

1. 将候选结构改为指针/索引加分数，避免复制 embedding。
2. 提取统一的 `isBetterCandidate()` 比较函数，同时供堆和最终排序使用。
3. 遍历时执行 threshold 过滤并维护容量为 K 的最小堆。
4. 将堆中候选转成轻量数组，按“分数降序、名称升序”排序。
5. 最后才复制 K 个工具元数据到返回结果。
6. 增加全排序参考实现，仅用于测试中比对随机数据结果。
7. 增加 benchmark，确认优化不是只有理论收益。

## 8. 测试与基准

正确性测试：

- `K = 0/1/N/N+1`；
- 负数 K；
- 相同相似度的稳定顺序；
- 全部低于 threshold；
- 部分向量维度错误；
- 零向量、`NaN`、`Inf`；
- 随机数据下与全排序参考实现逐项比对。

性能测试建议覆盖：

| N | K | D |
|---:|---:|---:|
| 100 | 5 / 10 | 1536 |
| 1,000 | 5 / 20 / 100 | 1536 |
| 10,000 | 10 / 100 | 1536 |

分别比较：

- 当前全排序；
- `std::nth_element`；
- 固定容量最小堆；
- 最小堆 + 预归一化；
- 是否复制完整 embedding。

输出 P50/P95 耗时、临时内存和结果一致性。预期在 `K << N` 时最小堆明显减少排序与内存开销；如果 `N` 很小，三种方案差异有限，此时应优先保留代码清晰度。

## 9. 面试介绍建议

可以将该优化描述为：

> 初版为了验证 RAG 工具路由，使用全量余弦打分和全排序，复杂度为 `O(ND + N log N)`。在分析查询路径后，将候选选择改为固定容量最小堆，并只保存工具引用和分数，使排序阶段降为 `O(N log K)`、候选空间降为 `O(K)`；同时通过稳定二级排序和参考实现随机对拍保证结果一致。随后进一步预归一化向量，把余弦计算简化为点积。

这段介绍同时覆盖了问题识别、数据结构选择、复杂度分析、工程权衡和验证方法，比直接引入复杂的 ANN 库更容易体现对算法和系统设计的理解。
